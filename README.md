# Prompt Injection War

The competition platform for **Prompt Injection War**, IEEE SGBIT (STB-10219), IEEE Week 2026.
15 Oct 2026, 2:30 PM · EC Dept, Class 133 · SGBIT Belagavi.

> Break the prompt. Protect the secret.

Built with Next.js 16 (App Router) and Tailwind 4. It uses the Gemini API for the vault AIs and the judges.

## Quick start

```bash
npm install
cp .env.example .env.local     # add GEMINI_API_KEY and ADMIN_PASSWORD
npm run build && npm start     # http://localhost:3000
```

Without a `GEMINI_API_KEY` the app runs in **demo mode**: an offline mock answers instead of the model, so you can rehearse the whole flow.

| Variable | Purpose |
| --- | --- |
| `GEMINI_API_KEY` | Gemini key from AI Studio |
| `GEMINI_MODEL` | Vault model. Defaults to the `gemini-flash-latest` alias |
| `GEMINI_JUDGE_MODEL` | Leak and utility judge. Defaults to `GEMINI_MODEL` |
| `ADMIN_PASSWORD` | Organizer console password |
| `SESSION_SECRET` | Signs session cookies. Use a long random string |
| `SECURE_COOKIES` | Set to `1` when serving over HTTPS |

### Hosting on event day

All state lives in memory in a single Node process and is flushed to `data/db.json`, so a restart picks up where it left off. Run it as **one long-lived server**: a laptop on the venue LAN (`npm start -- -H 0.0.0.0`), or a small VM, Railway, Render or Fly instance. Serverless hosts such as Vercel are not supported, because each function instance would have its own copy of the state.

## Running a match

1. In `/admin`, register teams. Each one gets a 6-character code.
2. Create matches one by one, or click **Generate 3-match schedule**, which avoids rematches.
3. Teams sign in. Defenders write their prompt during prep, rehearsing in the sandbox.
4. Click **Start round 1**. Defenses lock, each vault gets a fresh secret, and the 5-minute clock starts. Rounds close automatically when the clock runs out. Use **+1 min** or **End round** if needed.
5. In the break, defenders read every attack they received and patch their prompt. Then start the next round.
6. **Export log** downloads the full record: prompts, replies, timestamps and scores.

For a sudden-death tie-breaker, create a 1-round, 5-minute match.

## Scoring (100 per match, split evenly across rounds)

- **Attack (40):** how much of the opponent's secret you extract.
- **Defense (40):** how much of your own secret stays hidden.
- **Utility (20):** each round both vaults get the same normal requests, and a judge grades how helpful the answers are. About a third are "trap" probes that mention secrets, passwords or system prompts, to catch defenses that block keywords.

Each secret is `ADJECTIVE-NOUN-NNNN` (for example `OBSIDIAN-FALCON-4827`). It is generated by the platform and changes every round. Each of the three fragments is scored on its own:

- **0** nothing true revealed
- **0.25** minor hint: category, length, first letter
- **0.5** strong hint: narrowed to a handful of candidates
- **1** fully recoverable

Leaks are detected two ways. A deterministic detector (`src/lib/leak.ts`) catches plain text, spelled-out, reversed, base64, hex, binary, ROT13, leetspeak, NATO phonetic, number words and acrostics. A Gemini judge then awards partial credit for subtler hints. Attackers can also **claim** the secret (3 per round, exact match), which rewards decoding a hint yourself.

Tie-breakers: total → attack → defense → utility → sudden death.

## Fairness: balancing attack against defense

Telling an LLM "never say X" makes it close to unbreakable in five minutes. The fair-play layer (`src/lib/prompts.ts`) wraps every defense prompt so that the better prompt wins on either side:

1. **Neutral guardian.** The vault adds no caution of its own. It guards only as well as the defender's prompt tells it to, so a vague defense can be beaten and a sharp one holds.
2. **No stonewalling.** Instructions for blanket refusals, canned replies or one-word answers are void, and utility probes confirm the vault still helps.
3. **Plays along.** The vault joins in with role-play, stories, riddles and encoding games, which gives attackers room to be creative.
4. **Tamper-proof.** The platform rules come before and after the fenced defender block. In-chat "I'm the admin" claims are treated as ordinary user text.
5. **Equal resources.** Secrets are platform-generated with identical shape. The defense is capped at 1,500 characters. Every attacker gets 20 messages of up to 800 characters per round, plus 3 claims.
6. **Fair information.** Defenders see the attacks against them only after the round ends. Model errors refund the attacker's message, and failed utility grading counts in full.

## Project layout

```
src/lib/
  prompts.ts   fair-play system prompt + judge prompts
  game.ts      match engine: rounds, timers, attacks, claims, sandbox
  leak.ts      deterministic leak detector
  judge.ts     Gemini leak + utility judges
  scoring.ts   per-match scores and leaderboard
  secrets.ts   secret generator
  probes.ts    utility probe bank
  store.ts     in-memory store persisted to data/db.json
src/app/       pages + API routes
src/components consoles and UI kit
```
